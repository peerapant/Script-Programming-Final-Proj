### 1. วัตถุประสงค์และขอบเขตโครงการ (Project Purpose & Scope)

ในการวิเคราะห์ตัวอย่างหินด้วยกล้องจุลทรรศน์อิเล็กตรอนแบบส่องกราด (SEM) ไฟล์ภาพถ่ายที่ส่งออกจากเครื่องมักมีชื่อไฟล์เป็นรหัสตัวเลขดิบที่ยากต่อการสืบค้น และข้อมูลสเปกตรัม/กำลังขยายจะกระจัดกระจายอยู่ในตารางบันทึกการทดลอง (Excel)

โปรเจกต์นี้มีเป้าหมายเพื่อพัฒนาสคริปต์ Python สำหรับประมวลผลภาพถ่าย SEM อัตโนมัติ โดยทำหน้าที่:

* ดึงข้อมูลรหัสตัวอย่างและวันที่จากไฟล์บันทึกการทดลอง (Excel)
* สกัดค่ากำลังขยาย (Magnification) จากตัวเลขบนภาพถ่ายด้วยกระบวนการ Image Pre-processing และ EasyOCR
* รวมข้อมูลและเปลี่ยนชื่อไฟล์ให้อยู่ในฟอร์แมตมาตรฐาน `[ชื่อหิน]-[จุดถ่าย].[ลำดับซูม]_[กำลังขยาย].[นามสกุล]`

### 2. สถาปัตยกรรมระบบ (Modular Architecture & Separation of Concerns)

โปรแกรมถูกออกแบบแยกหน้าที่เป็น 3 โมดูลหลัก ตามหลักการออกแบบเชิงซอฟต์แวร์ (Separation of Concerns):

```text
┌────────────────────────────────────────────────────────────────────────┐
│                        MODULE 1: DATA & I/O LAYER                      │
│  - Excel Reader (Pandas/openpyxl)                                      │
│  - Date Normalizer (จัดการ พ.ศ./ค.ศ., DDMMYY, YYYY-MM-DD)               │
│  - String Sanitizer & ID Cleaner                                       │
└──────────────────────────────────┬─────────────────────────────────────┘
                                   │
                                   ▼
┌────────────────────────────────────────────────────────────────────────┐
│                    MODULE 2: IMAGE PRE-PROCESSING & OCR                │
│  - Dynamic Relative Crop Box (คำนวณตำแหน่ง % ตาม Resolution ภาพ)       │
│  - Color Space Conversion (RGBA/RGB -> Grayscale)                      │
│  - Otsu Thresholding & Erosion (ลด Noise และปรับ Contrast อัตโนมัติ)      │
│  - EasyOCR Engine (ดึงตัวเลขและสัญลักษณ์กำลังขยาย)                         │
└──────────────────────────────────┬─────────────────────────────────────┘
                                   │
                                   ▼
┌────────────────────────────────────────────────────────────────────────┐
│                    MODULE 3: BUSINESS LOGIC & EXECUTION                │
│  - Mapping Engine (คีย์ร่วม: Date + ID)                                   │
│  - Naming & Counter Engine (นับลำดับ Point และ Zoom อัตโนมัติ)             │
│  - Safe Dry-Run Mode & Interactive HTML Renderer (UI)                  │
└────────────────────────────────────────────────────────────────────────┘

```

### 3. นิยามความเสร็จสมบูรณ์ของงาน (Definition of Done - DoD)

งานใน Sprint 1 จะถือว่าเสร็จสมบูรณ์ (Done) เมื่อผ่านเกณฑ์ต่อไปนี้ทุกข้อ:

* [x] **Data Persistence & Normalization:** สามารถอ่านไฟล์ Excel เติมข้อมูลที่เว้นว่างแบบ `ffill` และแปลงวันที่ในรูปแบบต่างๆ ให้เป็นมาตรฐาน `YYYY-MM-DD` ได้ 100%
* [x] **Adaptive OCR:** สามารถอ่านค่ากำลังขยายจากภาพ SEM ที่มีขนาด Resolution แตกต่างกันได้ถูกต้อง โดยไม่เกิดปัญหาพิกัดพังจากการ Hardcode พิกเซล
* [x] **Robust Pre-Processing:** สามารถประมวลผลภาพถ่ายที่มีความสว่างต่างกันโดยใช้ Otsu Binarization เพื่อสกัดตัวเลขได้แม่นยำ
* [x] **Naming Logic Continuity:** คำนวณลำดับจุดถ่าย (Point) และลำดับกำลังขยาย (Zoom) ต่อเนื่องถูกต้องเมื่อพบตัวอย่างชนิดเดิม
* [x] **Edge Case Resilience:** หากไม่พบข้อมูลใน Excel หรือ OCR อ่านค่าล้มเหลว ระบบต้องไม่ Crash แต่ใช้ชื่อสำรอง (`Unknown_[ID]`) เพื่อรักษาสถานะของโปรแกรม
* [x] **Safe Preview UI:** มีระบบ Dry-run Mode ที่แสดงผลลัพธ์เป็นตาราง HTML เปรียบเทียบชื่อเดิม-ชื่อใหม่ บน Google Colab ก่อนทำการ rename ไฟล์จริง

### 💡 Whoops! (ปัญหาที่พบและแนวทางการแก้ไข)

1. **ปัญหา Google Drive Mount ค้างใน Colab:**
* *ปัญหา:* การ Mount Drive ผ่านสคริปต์อัตโนมัติในบางเซสชันเกิดอาการ Timeout ค้าง
* *แนวทางแก้ไข:* ปรับเปลี่ยนกระบวนการเป็นการยืนยันผ่าน UI Mount ของ Colab และเพิ่ม Validation Checkpoint ตรวจสอบความมีอยู่จริงของ `EXCEL_PATH` และ `DATA_FOLDER` ก่อนเริ่ม Pipeline


2. **ปัญหาพิกัด Crop เบี้ยวเมื่อเปลี่ยนขนาดภาพ (Resolution Mismatch):**
* *ปัญหา:* เดิมทีการใช้พิกัดพิกเซลคงที่ (Hardcoded Pixels) ทำให้ตำแหน่งตัดขอบภาพเบี้ยวเมื่อเจอฟอร์แมตภาพขนาดต่างกัน
* *แนวทางแก้ไข:* เปลี่ยนมาคำนวณสัดส่วนแบบ **Relative Crop Ratio** `(ymin, xmin, ymax, xmax)` อิงตาม % ความกว้างและความสูง (W, H) ของแต่ละภาพจริง


3. **ปัญหาคอลัมน์ ID ใน Excel อ่านติดทศนิยม `.0`:**
* *ปัญหา:* `pandas.read_excel()` อ่านค่า ID ตัวเลขแล้วแปลงเป็น float เช่น `101.0` ทำให้ Key ไม่ตรงกับไฟล์ภาพ
* *แนวทางแก้ไข:* เพิ่มฟังก์ชัน `clean_id()` ใน Data Cleaning Layer เพื่อตัดข้อความ `.0` ท้ายสตริงและลบช่องว่างอัตโนมัติ ก่อนนำไปสร้าง Mapping Key
